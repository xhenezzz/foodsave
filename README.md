# 🌿 FoodSave

**FoodSave** — веб-платформа для продажи продуктов с приближающимся сроком годности по сниженным ценам и сокращения пищевых отходов в Казахстане.

**Магазины, пекарни и кафе** публикуют товары, которые ещё пригодны к употреблению, а **покупатели** находят предложения в своём городе, бронируют, оплачивают онлайн и забирают по QR-коду в указанное время. Бизнес уменьшает потери, покупатели экономят, а еда не попадает в отходы.

> **Статус:** учебный / дипломный прототип. Платежи работают через Stripe в **тестовом режиме** — реальных списаний нет.

## 📌 Возможности

| Для покупателя (`CUSTOMER`) | Для бизнеса (`BUSINESS`) |
| --- | --- |
| Регистрация с подтверждением email | Регистрация с подтверждением email |
| Каталог предложений своего города (Алматы / Астана) | Профиль заведения с точкой на карте |
| Поиск по названию, поиск рядом и карта | Создание, редактирование и отмена объявлений |
| Сортировка: рекомендации, скидка, цена, расстояние | До 5 фотографий на объявление |
| Бронирование и оплата через Stripe Embedded Checkout | AI-черновик объявления по фото (Gemini) |
| QR-код для получения заказа | Подтверждение выдачи по QR (камера или ручной ввод) |
| Отзывы о заведении | Статистика: выручка, топ-продуктов, спасённая еда, CO₂ |
| FoodPoints, репутация и статистика вклада | Рейтинг и отзывы |

Роли разделены: покупатель не видит кабинет бизнеса, бизнес работает только со **своими** объявлениями (`/api/listings/my`). Права и владелец ресурса проверяются на **backend** (Spring Security), а не только в React.

### Админ-панель (`ADMIN`)

Администратор после входа попадает на `/admin`:

| Раздел | Что можно сделать |
| --- | --- |
| **Обзор** | Пользователи по ролям, объявления, заказы, оплаты и выручка, спасённая еда и CO₂, график активности за 14 дней, статусы заказов, топ-5 заведений |
| **Пользователи** | Поиск по имени, email или телефону, фильтр по роли, **блокировка и разблокировка** с причиной |
| **Объявления** | Поиск и фильтр по статусу, **снятие с публикации** (модерация) |
| **Заказы** | Все заказы платформы с фильтром по статусу, статусом оплаты и суммой |

- Заблокированный пользователь сразу теряет доступ: вход и все запросы с уже выданным JWT отклоняются (флаг перечитывается из БД на каждом запросе). При входе он видит причину блокировки.
- Администратора (в том числе себя) заблокировать нельзя.
- Публичная регистрация админов невозможна. Первый администратор создаётся при запуске backend из переменных `ADMIN_*` в `.env` (см. ниже). Существующий аккаунт с тем же email не повышается и не изменяется.
- Списки ограничены 200 строками — уточняйте поиск фильтрами.

### Жизненный цикл заказа

1. Покупатель бронирует товар → заказ `RESERVED`, количество в объявлении уменьшается.
2. На оплату даётся **15 минут** (но не дольше окончания выдачи). Неоплаченная бронь становится `EXPIRED`, товар возвращается в продажу.
3. Оплата через Stripe подтверждается **webhook-ом на сервере**, а не редиректом браузера. Если заказ к моменту оплаты стал недоступен, платёж автоматически возвращается.
4. После оплаты доступен QR-код. Бизнес сканирует его → заказ `COMPLETED`, покупателю начисляется **+10 FoodPoints**.
5. Если оплаченный заказ не забрали в течение 15 минут после окончания выдачи → `NO_SHOW`, **−5 FoodPoints**. Каждое третье нарушение блокирует новые бронирования на 7 дней.

### Рекомендательная система

Rule-based ранжирование предложений:

| Критерий | Вес |
| --- | ---: |
| Размер скидки | 40% |
| Рейтинг заведения | 25% |
| Количество доступных товаров | 15% |
| Расстояние до покупателя | 20% |

Основной источник — поле `recommendationScore` (0–100) от Spring Boot. Если его нет, frontend считает резервную оценку. Без геолокации критерий расстояния исключается, а остальные веса нормализуются. Распроданные, истёкшие и просроченные предложения в подборку не попадают.

## 🛠 Технологии

**Backend:** Java 17+ (рекомендуется JDK 21), Spring Boot 4, Spring Security + JWT, Spring Data JPA, PostgreSQL, Flyway, Spring Mail (Gmail SMTP), Stripe Java SDK, Google Gemini API, геокодирование Nominatim (OpenStreetMap).

**Frontend:** React 19, TypeScript, Vite 6, CSS, Lucide React, Leaflet 1.9 + тайлы OpenStreetMap (загружается через CDN), Stripe.js.

**Архитектура:** клиент-серверное веб-приложение. Frontend обращается к REST API по HTTP; данные и проверки доступа живут на сервере.

## 🚀 Запуск локально

### 1. Что потребуется

- Git
- **JDK 17+** (рекомендуется Temurin 21). Нужен именно JDK, а не JRE — иначе Maven выдаст `No compiler is provided in this environment`.
- **Node.js 22+** и npm
- PostgreSQL
- Интернет: npm-пакеты, карта, Stripe.js, Gemini, Nominatim

### 2. Клонировать

```bash
git clone https://github.com/xhenezzz/foodsave.git
cd foodsave
```

### 3. Создать базу данных

```sql
CREATE DATABASE foodsave_db;
```

Схема создаётся **Flyway** при запуске (`spring.jpa.hibernate.ddl-auto=validate`). Если база уже содержит таблицы, созданные до Flyway, первый запуск выполни с `FLYWAY_BASELINE_ON_MIGRATE=true`.

### 4. Файл `.env` для backend

В корне проекта создай `.env` (он в `.gitignore`, **не коммить его**). Spring Boot читает его автоматически (`spring.config.import=optional:file:./.env[.properties]`).

```properties
DB_URL=jdbc:postgresql://localhost:5432/foodsave_db
DB_USER=postgres
DB_PASSWORD=<пароль PostgreSQL>

JWT_SECRET=<длинная случайная строка, Base64>
JWT_EXPIRATION_MS=86400000

# Письма подтверждения (для Gmail нужен «пароль приложения»)
MAIL_USERNAME=<ваш_адрес>@gmail.com
MAIL_PASSWORD=<пароль приложения>

# Stripe (тестовые ключи из Dashboard → Developers)
STRIPE_SECRET_KEY=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...
STRIPE_CURRENCY=kzt
FRONTEND_URL=http://localhost:5173

# AI-черновики объявлений (необязательно)
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.1-flash-lite

FLYWAY_BASELINE_ON_MIGRATE=false

# Первый администратор (необязательно). Создаётся при запуске, если такого email ещё нет.
ADMIN_EMAIL=admin@foodsave.local
ADMIN_PASSWORD=<8–64 символа>
ADMIN_USERNAME=admin
ADMIN_PHONE=+77000000000
```

| Переменная | Обязательна | Без неё |
| --- | --- | --- |
| `DB_*`, `JWT_SECRET` | да | backend не запустится |
| `MAIL_*` | да | регистрация завершится ошибкой «Не удалось отправить письмо», аккаунт не создаётся |
| `STRIPE_SECRET_KEY` | для оплаты | кнопка «Оплатить» вернёт «Stripe не настроен» |
| `STRIPE_WEBHOOK_SECRET` | для оплаты | платёж не будет подтверждён сервером |
| `GEMINI_API_KEY` | нет | AI-черновик по фото недоступен, остальное работает |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | для админ-панели | администратор не создаётся; `ADMIN_PHONE` должен быть уникальным и в формате `+7XXXXXXXXXX` |

### 5. Файл `.env.local` для frontend

В `foodsave-frontend/.env.local`:

```properties
VITE_API_URL=http://localhost:8081/api
VITE_STRIPE_PUBLISHABLE_KEY=pk_test_...
```

`VITE_API_URL` можно не указывать — по умолчанию используется `http://localhost:8081/api`.

### 6. Запустить

**Вариант А — скрипты для Windows.** Первый раз запусти `setup_foodsave.bat`: он поставит недостающие JDK/Node.js через winget, создаст БД, соберёт и запустит проект. Дальше — `start_foodsave.bat` (откроет два окна: backend :8081 и frontend :5173).

> ⚠️ `run_backend.ps1` запускает **уже собранный** jar из `target/` и пересобирает его, только если jar отсутствует. После `git pull` или изменений в Java-коде пересобери backend:
> ```powershell
> .\mvnw.cmd -DskipTests package
> ```

**Вариант Б — вручную**, в двух терминалах:

```powershell
# Терминал 1 — backend (из корня проекта)
$env:JAVA_HOME="C:\Program Files\Eclipse Adoptium\<папка JDK>"
.\mvnw.cmd spring-boot:run
```

```bash
# Терминал 2 — frontend
cd foodsave-frontend
npm install
npm run dev
```

Linux/macOS: `./mvnw spring-boot:run`.

Открой **http://localhost:5173**.

### 7. Stripe webhook локально

Stripe должен достучаться до `POST /api/payments/stripe/webhook`. Для локальной разработки используй [Stripe CLI](https://docs.stripe.com/stripe-cli):

```bash
stripe listen --forward-to localhost:8081/api/payments/stripe/webhook
```

Команда выведет `whsec_...` — подставь его в `STRIPE_WEBHOOK_SECRET` и перезапусти backend. Тестовая карта: `4242 4242 4242 4242`, любая будущая дата и CVC.

### 8. Проверить работу

1. Зарегистрируй аккаунт `CUSTOMER` (город `ALMATY` или `ASTANA`, телефон в формате `+7XXXXXXXXXX` или `8XXXXXXXXXX`), подтверди почту по ссылке из письма.
2. Создай второй аккаунт `BUSINESS`, заполни профиль заведения и **поставь метку на карте** — именно эти координаты сохранятся (метка должна быть в пределах твоего города). Опубликуй объявление на `/business`.
3. Покупателем открой `/discover`, забронируй товар, оплати на `/orders` тестовой картой.
4. Открой QR заказа и отсканируй его из кабинета бизнеса (или вставь токен вручную) — заказ станет `COMPLETED`.
5. Проверь FoodPoints, репутацию, статистику вклада, отзыв и статистику бизнеса.
6. Войди под `ADMIN_EMAIL` — откроется `/admin`. Заблокируй тестового покупателя и убедись, что он не может войти; разблокируй.

### Формат ошибок

Все ошибки возвращаются единообразно — `GlobalExceptionHandler` превращает исключения сервисов в JSON с понятным сообщением и правильным HTTP-статусом:

```json
{ "message": "Неверный логин или пароль" }
```

| Статус | Когда |
| --- | --- |
| `400` | Ошибка валидации или бизнес-правила |
| `401` | Неверный логин/пароль, нет авторизации |
| `403` | Недостаточно прав, почта не подтверждена, бронирования заблокированы |
| `404` | Ресурс не найден (например, профиль бизнеса ещё не создан) |
| `409` | Конфликт состояния: заказ уже нельзя отменить, объявление изменилось и т. п. |
| `503` | Не настроен внешний сервис (Stripe, Gemini) или не отправилось письмо |
| `500` | Непредвиденная ошибка — подробности только в логе сервера |

Frontend показывает `message` в уведомлении, а HTTP-статус доступен через `ApiError.status` (`httpStatus(error)` в `api.ts`). При `401`/`403` во время загрузки данных пользователь разлогинивается с сообщением «Сессия истекла».

## ✨ Анимации интерфейса

Слой анимаций вынесен в `foodsave-frontend/src/animations.css` и подключается последним в `main.tsx`:

- плавные переходы между страницами;
- «парящая» еда и карточки на главной;
- поочерёдное появление карточек предложений, заказов, объявлений и KPI (индекс передаётся через CSS-переменную `--i`, хелпер `stagger()` в `utils.ts`);
- счётчики со «счётом» до значения — компонент `CountUp`;
- появление модальных окон и уведомлений, полоска таймера у уведомления, «встряхивание» ошибок;
- прорисовка линии графика выручки и заполнение прогресс-бара;
- сканирующая линия на QR-коде, микро-анимации кнопок, бейджей и звёзд отзыва.

Объёмный слой — `effects3d.css` + `effects3d.ts` (подключаются в `main.tsx`):

- **3D-наклон карточек за курсором** с бликом — атрибут `data-tilt` (карточки предложений, KPI, статистика, админ-карточки). Один делегированный обработчик на всю страницу, обновление через `requestAnimationFrame`;
- **3D-сцена на главной**: тарелка, фон и плашки стоят на разной глубине (`translate: 0 0 Npx`) и расходятся при наклоне; вокруг тарелки вращается светящееся кольцо;
- **появление секций при прокрутке** с 3D-разворотом — атрибут `data-reveal` (IntersectionObserver + MutationObserver для страниц, отрисованных позже);
- **«северное сияние»** — медленно плывущий градиентный фон, стеклянная шапка с бегущей подсветкой, переливающийся градиент заголовков;
- **«нажимные» 3D-кнопки** с торцом и тенью;
- в админ-панели — вращающийся стеклянный 3D-куб с орбитой, скользящий индикатор вкладок, разворот панели при смене вкладки, вырастающие столбцы графика и «встающий» донат-график.

На сенсорных экранах наклон за курсором не включается.

Анимации чисто декоративные: интерфейс корректно выглядит и без них. При включённой в системе настройке **«уменьшить движение»** (`prefers-reduced-motion`) все анимации отключаются.

## ❗ Возможные проблемы

| Симптом | Что проверить |
| --- | --- |
| `Failed to fetch`, `ERR_CONNECTION_REFUSED` | Запущен ли backend на `localhost:8081`; `VITE_API_URL` |
| Ошибка CORS | Frontend должен открываться с `localhost` или `127.0.0.1` (другие origin не разрешены в `SecurityConfig`) |
| `No compiler is provided in this environment` | `JAVA_HOME` указывает на JRE — укажи папку JDK |
| «Не удалось отправить письмо» при регистрации | `MAIL_USERNAME` / `MAIL_PASSWORD` (для Gmail — пароль приложения) |
| «Подтвердите электронную почту» при входе | Открой ссылку из письма (действует 30 минут) или запроси письмо повторно |
| «Сессия истекла» | JWT истёк — войди снова |
| «Введите корректный номер телефона Казахстана» | Формат `+7XXXXXXXXXX` или `8XXXXXXXXXX` |
| «Метка на карте должна находиться в пределах города» | Метка заведения дальше 90 км от центра города из профиля |
| «Stripe не настроен» / платёж висит в ожидании | `STRIPE_SECRET_KEY`, запущен ли `stripe listen`, совпадает ли `STRIPE_WEBHOOK_SECRET` |
| Не открывается форма оплаты | `VITE_STRIPE_PUBLISHABLE_KEY` в `foodsave-frontend/.env.local` |
| «Gemini не настроен» | `GEMINI_API_KEY` (функция необязательная) |
| Пустой каталог | Город в профиле, координаты бизнеса, сроки объявления и годности продукта |
| Не отображается карта | Интернет, доступ к Leaflet CDN / OpenStreetMap, разрешение геолокации |
| Изменения backend «не применились» после `start_foodsave` | Пересобери jar: `.\mvnw.cmd -DskipTests package` |
| Flyway: `found non-empty schema` | Один раз запусти с `FLYWAY_BASELINE_ON_MIGRATE=true` |
| «Аккаунт заблокирован администратором» | Разблокируй пользователя в `/admin` → «Пользователи» |
| Администратор не появился | `ADMIN_EMAIL` / `ADMIN_PASSWORD` в `.env`, пароль 8–64 символа, `ADMIN_PHONE` не занят; смотри предупреждение в логе backend |
| `403` на `/api/admin/*` | Вход выполнен не под ролью `ADMIN` |

### Ограничения прототипа

- Город в URL (`?city=ALMATY`) — фильтр, а **не механизм авторизации**.
- Статус «оплачено» берётся только с сервера (webhook Stripe); редирект из Stripe сам по себе ничего не подтверждает.
- Возвраты денег выполняются автоматически лишь в одном случае — если заказ стал недоступен к моменту оплаты. Оплаченный заказ отменить нельзя.
- Сканирование QR камерой зависит от поддержки `BarcodeDetector` в браузере; есть ручной ввод токена.
- Ссылка в письме подтверждения и QR профиля сейчас ведут на `http://localhost:5173`.
- Для продакшена нужны отдельная конфигурация окружения, HTTPS, безопасное хранение секретов и боевые ключи Stripe.

## 📝 Последние изменения

**Админ-панель и 3D-интерфейс**
- Роль `ADMIN` с панелью `/admin`: обзор платформы, пользователи с блокировкой, модерация объявлений, все заказы.
- Миграция `V5__user_blocking.sql`: поля `blocked` и `blocked_reason` у пользователей; блокировка действует сразу.
- Создание первого администратора из `ADMIN_*` в `.env`.
- Новый визуальный слой: 3D-наклон карточек, 3D-сцена на главной, появление секций при прокрутке, анимированный фон, стеклянные поверхности, объёмные кнопки.

**Исправления backend**
- Единый обработчик ошибок: вместо «голого» HTTP 500 клиент получает понятное сообщение и корректный статус (401 при неверном пароле, 404 для отсутствующего профиля бизнеса и т. д.).
- Профиль бизнеса сохраняет точку, выбранную на карте (раньше она заменялась геокодированием адреса).
- Новый бизнес без профиля больше не получает ошибку в кабинете — `/listings/my` возвращает пустой список.
- `PUT /profile/me` проверяет email, телефон и город.
- Профиль возвращает `emailVerified`; надёжность без истории заказов — «—», как в разделе репутации.
- Регистрация транзакционна: если письмо не отправилось, «зависший» аккаунт не создаётся.
- Длина комментария отзыва проверяется до записи в БД.
- Тесты снова компилируются и проходят (переписан тест Stripe-платежей, исправлен тест AI).

**Исправления frontend**
- Двойной клик больше не создаёт два бронирования / два отзыва / двойное сохранение.
- Формат телефона совпадает с backend.
- После возврата из Stripe корректно открывается страница заказов.
- Истёкшая сессия корректно разлогинивает пользователя.
- Кнопки оплаты больше не подписаны как «демо».
- Модальные окна закрываются клавишей Esc.

**Новое в интерфейсе** — анимации (см. раздел «✨ Анимации интерфейса»).
