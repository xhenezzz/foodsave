# 🌿 FoodSave

**FoodSave** — веб-платформа для продажи продуктов с приближающимся сроком годности по сниженным ценам и сокращения пищевых отходов в Казахстане.

Идея приложения проста: **магазины, пекарни и кафе** публикуют товары, которые ещё пригодны к употреблению, а **покупатели** находят предложения в своём городе, бронируют их и забирают в указанное время. Это помогает бизнесу уменьшать потери, покупателям — экономить, а обществу — снижать количество выбрасываемой еды.

> **Статус:** учебный / дипломный прототип. Для полноценной работы необходим запущенный backend FoodSave. Часть возможностей (например, расширенная экологическая статистика и платёжная интеграция) зависит от реализации соответствующих API на сервере.

## 📌 Возможности

| Для покупателя (`CUSTOMER`) | Для бизнеса (`BUSINESS`) |
| --- | --- |
| Регистрация и вход | Регистрация и вход |
| Просмотр предложений своего города (Алматы / Астана) | Создание и редактирование профиля заведения |
| Поиск продуктов поблизости и отображение на карте | Создание, редактирование и отмена своих объявлений |
| Сортировка по рекомендациям, скидке, цене и расстоянию | Просмотр собственных объявлений |
| Бронирование и просмотр заказов | Подтверждение выдачи заказа по QR-коду |
| Оплата заказа через API приложения и QR для получения | Просмотр отзывов и рейтинга |
| Отзывы, FoodPoints и статистика | — |

Роли разделены: покупатель не получает доступ к кабинету бизнеса, а бизнес работает со **своими** объявлениями через `/api/listings/my`. Окончательные проверки прав и владельца ресурса должны выполняться на **backend**, не только в React.

### Рекомендательная система

FoodSave использует **rule-based** алгоритм ранжирования товаров:

| Критерий | Вес |
| --- | ---: |
| Размер скидки | 40% |
| Рейтинг заведения | 25% |
| Количество доступных товаров | 15% |
| Расстояние до покупателя | 20% |

Основной источник оценки — поле `recommendationScore` (0–100), возвращаемое Spring Boot. Если поле отсутствует, frontend использует резервный расчёт. При отсутствии геолокации недоступный критерий расстояния исключается из расчёта с нормализацией оставшихся весов. Недоступные, распроданные и истёкшие предложения не должны участвовать в подборке.

## 🛠 Технологии

**Frontend:** React 19, TypeScript, Vite 6, CSS, Lucide React. Для интерактивной карты используются Leaflet 1.9.4 и тайлы OpenStreetMap (Leaflet загружается через CDN).

**Backend:** Java, Spring Boot, Spring Security, JWT, Spring Data JPA и PostgreSQL. Backend — отдельная часть проекта, предоставляющая REST API.

**Архитектура:** клиент-серверное веб-приложение. Frontend обращается к REST API по HTTP; данные и проверки доступа хранятся и выполняются на стороне сервера.

В приложении три маршрута:

| URL | Назначение | Роль |
| --- | --- | --- |
| `/discover` | Каталог товаров и карта | `CUSTOMER` |
| `/orders` | Мои заказы, оплата, QR, статистика | `CUSTOMER` |
| `/business` | Кабинет заведения, объявления, QR-сканер | `BUSINESS` |

Маршрутизация реализована через браузерный **History API** (`pushState` / `popstate`), без `react-router-dom`. Авторизация, профиль, статистика и некоторые операции открываются в модальных окнах, а не на отдельных страницах.

## 🚀 Как запустить проект локально

### 1. Что потребуется

- Git (для клонирования репозитория).
- **Node.js 22+** и npm (Node.js 22+ также используется для запуска имеющихся тестов).
- Java и Maven **версий, соответствующих `pom.xml` backend** (при наличии `mvnw` можно использовать Maven Wrapper).
- PostgreSQL, запущенный локально или через Docker.
- Интернет для загрузки npm-пакетов и карты Leaflet / OpenStreetMap.

### 2. Клонировать репозиторий

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd <ПАПКА_РЕПОЗИТОРИЯ>
```

Если backend и frontend находятся в разных репозиториях, их необходимо клонировать отдельно. Команды ниже выполняются в корнях соответствующих проектов.

### 3. Настроить PostgreSQL и backend

Создай в PostgreSQL базу данных (например, `foodsave_db`):

```sql
CREATE DATABASE foodsave_db;
```

Проверь `application.properties` или `application.yml` в Spring Boot. **Пример** настроек для локальной разработки (значения необходимо адаптировать к своему окружению):

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/foodsave_db
spring.datasource.username=postgres
spring.datasource.password=${DB_PASSWORD}

server.port=8081
```

`DB_PASSWORD` — переменная окружения с паролем к PostgreSQL. Настрой также все обязательные параметры JWT и прочие свойства, которые используются **именно в твоём backend**. Их названия и способ задания нужно проверить в исходном Spring Boot проекте. Не добавляй секретный JWT-ключ или реальный пароль базы в Git.

Для Windows PowerShell пример установки пароля в текущем окне терминала:

```powershell
$env:DB_PASSWORD="<ваш_пароль>"
```

Запусти backend из его корневой папки:

```powershell
# Windows, если в backend есть Maven Wrapper:
.\mvnw.cmd spring-boot:run
```

Для Linux/macOS (при наличии `mvnw`):

```bash
./mvnw spring-boot:run
```

Либо используй установленный Maven: `mvn spring-boot:run`.

Frontend настроен на адрес **`http://localhost:8081/api`**, поэтому backend должен слушать порт `8081`. Если сервер работает на другом адресе, измени константу `API_URL` в `src/api.ts`.

### 4. Запустить frontend

Открой **второй терминал** и перейди в папку `foodsave-frontend`:

```bash
cd foodsave-frontend
npm install
npm run dev
```

Открой в браузере: **http://localhost:5173**

> Если Vite выберет другой порт, используй URL, который он напишет в терминале.

### 5. Проверить работу

1. Создай аккаунт `CUSTOMER` с городом `ALMATY` или `ASTANA`.
2. Открой `/discover` и проверь список предложений, сортировку и поиск рядом (браузер запросит разрешение на геолокацию).
3. Выбери товар, оформи бронирование и открой `/orders`.
4. Для проверки бизнеса создай отдельный аккаунт с ролью `BUSINESS`, заполни профиль заведения и создай объявление на `/business`.
5. Проверь, что в кабинете бизнеса отображаются только собственные предложения.
6. Статистику проверяй после появления завершённых заказов; дополнительные показатели зависят от `/api/impact/my`.

**Важно для регистрации:** frontend отправляет в `/api/auth/register` поле `role` со значением `CUSTOMER` либо `BUSINESS`. Backend должен сохранить это значение (`user.setRole(role)`) и запрещать публичную регистрацию `ADMIN`.

## 🔌 Основные API

Базовый URL: `http://localhost:8081/api`

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/auth/register` | Регистрация |
| `POST` | `/auth/login` | Авторизация |
| `GET` | `/profile/me` | Профиль текущего пользователя |
| `GET` | `/listings?city=ALMATY` | Предложения по городу |
| `GET` | `/listings/nearby?latitude=43.2389&longitude=76.8897&radius=10&city=ALMATY` | Предложения рядом и рекомендации |
| `GET` | `/listings/my` | Объявления текущего бизнеса |
| `POST` | `/listings` | Создание объявления |
| `PUT` | `/listings/{id}` | Редактирование объявления |
| `DELETE` | `/listings/{id}` | Отмена объявления |
| `GET`, `POST`, `PUT` | `/business/profile` | Просмотр, создание и обновление бизнес-профиля |
| `POST` | `/orders` | Бронирование |
| `GET` | `/orders/my` | Мои заказы |
| `POST` | `/payments/{orderId}` | Оплата заказа |
| `GET` | `/orders/{id}/qr` | QR-код заказа |
| `POST` | `/orders/scan` | Подтверждение получения по QR |
| `GET` | `/impact/my` | Статистика FoodSave |
| `POST` | `/reviews` | Оставить отзыв |

Большинство методов требуют JWT в заголовке `Authorization: Bearer <token>`. Окончательные правила доступа определяются настройками Spring Security на сервере.

### Пример ответа с рекомендациями

```json
{
  "title": "Набор выпечки",
  "businessName": "Demo Bakery",
  "city": "ALMATY",
  "originalPrice": 3500,
  "foodSavePrice": 1750,
  "quantity": 5,
  "distanceKm": 1.6,
  "recommendationScore": 76.2
}
```

Это **пример части ответа**, а не данные реального объявления. Полная структура определяется `FoodListingResponse` на backend.

## ❗ Возможные проблемы

| Симптом | Что проверить |
| --- | --- |
| `Failed to fetch`, `ERR_CONNECTION_REFUSED` | Запущен ли backend на `localhost:8081`; верен ли `API_URL` |
| Ошибка CORS в браузере | Разрешён ли frontend origin `http://localhost:5173` в конфигурации Spring Security / CORS |
| `401 Unauthorized` | Токен JWT, его срок действия и вход в аккаунт |
| `403 Forbidden` | Правильная ли роль `CUSTOMER` / `BUSINESS`, разрешён ли метод сервером |
| Предложения другого города или пустой каталог | Поле `city` в ответе, координаты бизнеса и фильтр `/listings?city=...` |
| Не отображается карта | Интернет, разрешение на геолокацию, доступ к Leaflet CDN / OSM |
| Не работает «Статистика» | Существует ли `GET /api/impact/my`, HTTP-статус и формат ответа |
| После регистрации ошибка `Role.name()` | Убедись, что backend вызывает `user.setRole(role)` **до** сохранения и выдачи JWT |
| `npm run build` сообщает ошибку Rollup | Удали повреждённый `node_modules`, переустанови зависимости командой `npm install` на своей платформе |

### Ограничения прототипа

- Город в URL (`?city=ALMATY`) является фильтром, а **не механизмом авторизации**; ограничения доступа проверяются backend.
- Отображение «оплачено» должно опираться на подтверждённый статус платежа с сервера. Локально сохранённое состояние frontend не заменяет платёжную запись в БД.
- Значения FoodPoints и числа завершённых заказов приходят из профиля. Вес спасённой еды, экономия и CO₂e требуют корректно реализованного API статистики, а не вычисляются из выдуманных данных.
- Функции QR-сканирования камерой зависят от поддержки браузером `BarcodeDetector` и разрешения камеры; предусмотрен ручной ввод токена.
- Для продакшена понадобятся отдельная конфигурация окружения, безопасное хранение секретов, полноценные проверки доступа и тестирование платёжного сценария.
